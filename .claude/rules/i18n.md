# i18n (next-intl 4)

## Where text lives

- All UI strings: `messages/en.json` and `messages/ru.json` (root of repo, NOT `src/`)
- Both files MUST stay in sync — same key tree, every key present
- `data.ts` files (experience, projects, intExp) keep only meta (href, chips, year, organization name, projectName) — descriptions/dates/positions/bullets live in messages and are looked up by `key` / `i18nKey`

## Reading translations

- **Server Component** (async): `const t = await getTranslations('namespace')` then `t('key')`
- **Client Component** (`'use client'`): `const t = useTranslations('namespace')` then `t('key')`
- For arrays (bullets, items): `t.raw('items') as string[]`
- For inline rich-text (links inside a paragraph): `t.rich('key', { tagName: (chunks) => <El>{chunks}</El> })`

## Navigation (locale-aware)

- Use `Link`, `useRouter`, `usePathname`, `redirect` from `@/i18n/navigation` (created via `createNavigation(routing)`)
- `router.replace(pathname, { locale: 'ru' })` — switches locale while preserving the current route
- `localePrefix: 'as-needed'` — default locale (`en`) has no URL prefix; non-default locales prefixed (`/ru`)

## Adding a new key

1. Add in `en.json` (decide namespace: `header`, `about`, `nav`, `experience.items.<key>.…`, etc.)
2. Add the same key in `ru.json` with the Russian translation
3. Use it in the component via `t('key')`

## Adding a new locale

1. Add to `locales` array in `src/i18n/config.ts`
2. Create `messages/<locale>.json` mirroring `en.json`
3. Add the locale to `LanguageSwitcher` (already maps over `locales` from config — automatic)

## Metadata

- Localized in `app/[locale]/layout.tsx` via `generateMetadata`
- `await getTranslations({ locale, namespace: 'metadata' })`

## Locale state

- Active locale is exposed via `useLocale()` from `next-intl` (client) or read from `params.locale` (server)
- `<html lang={locale}>` set in root layout — important for accessibility / SEO

## Hard Rules

- NO hardcoded user-facing strings anywhere — always go through `t()`
- Don't store translation keys as strings in constant arrays (`labelKey: 'foo.bar'`) — they become dead strings invisible to refactor tools. Resolve at the call site.
- Keep `en.json` as the source of truth — translate to `ru.json` after.
